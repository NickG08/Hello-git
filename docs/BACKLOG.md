Отложенные идеи и открытые вопросы. Цифры — по снапшоту `fae1b9fb4a67` (2026-11-09, 397 строк: KASE 206, AIX 191).

## Идеи KPI

- **На обеих биржах.** 18 бумаг (по ISIN) торгуются и на KASE, и на AIX; уникальных бумаг 379, а не 397.
  Отдельная ячейка KPI: «На обеих биржах: 18 · уникальных бумаг 379». При фильтрах считать бумагу,
  только если видны обе её строки. Цены заметно расходятся (напр. KMGZe16 / KMG.0433: 90,31 на KASE
  против 100,00 на AIX) — показать обе котировки в карточке бумаги и метку в таблице.
- **Объём рынка.** Отложен. `issue_volume` теперь есть у всех бумаг, но: (1) 38 казначейских облигаций США
  на KASE несут глобальный объём выпуска (~$2,8 трлн), к рынку Казахстана он отношения не имеет;
  (2) объёмы в разных валютах — нужен либо разрез по валютам, либо пересчёт в USD по курсу.
  Возможная замена — оборот торгов (KASE `volusd`, AIX `value`), но его историю нужно копить.
- **Новые размещения за период.** Даты есть в источниках (KASE: «Дата включения в торговые списки»,
  AIX: `listingDate`), в снапшот пока не сохраняются.

## Данные эмитентов

- **Страна и категория эмитента.** Источники: KASE `/api/companies/issuers/{code}` (юр. адрес), AIX `country`
  в профиле (у 13 бумаг пусто или «XS» — все казахстанские). Итог: Казахстан 323 бумаги, иностранные
  суверены 58 (только KASE), иностранные корпоративные 10 (только AIX), наднациональные 6.
  Открытый вопрос: Kazakhmys Holding Group BV, Altyngold PLC, Ferro-Alloy Resources зарегистрированы
  за рубежом, но бизнес в Казахстане — к какой категории относить.
- **Дедупликация эмитентов.** KASE отдаёт названия по-русски, AIX — по-английски; 12 эмитентов
  есть на обеих биржах. По названиям 124 эмитента, с учётом совпадений 113. Решено пока считать по названиям.
- **Бумаги без даты погашения.** 12 недавно включённых бумаг KASE (почти все МФО): биржа ещё не
  опубликовала дату погашения и купон.

- **Проспекты.** Пайплайн читает проспекты KASE для бумаг с пробелами (`kzbonds/prospectus.py`).
  Документы AIX (`kzbonds/aix_docs.py`) читаются для бумаг AIX с пробелами: тот же публичный вызов,
  что делает просмотрщик K2, сканы распознаются tesseract. Не покрыто: у MIDMpp3, HK_01_2702,
  SA_05_2704 на KASE нет документов; у ALIF.1028 периодичность распределений в проспекте не указана;
  сканы без текстового слоя (MOBIpp1) не распознаются. У 12 выпусков ставка «определяется по итогам
  первых торгов» — её в проспекте нет.
- **YTM: формулы исправлены** (KASE — грязная цена и дробные периоды, сверено с доходностью KASE;
  AIX — купон по фактической длине периода, капитализация по проспекту). Дюрация больше срока до
  погашения больше не встречается.
- **YTM только по свежим сделкам.** Дата последней сделки сохраняется (`last_trade_date`; KASE —
  `date0`, AIX — история `/api/symbol/historical-specific/`). YTM и дюрация показываются, если сделка
  не старше `KZBONDS_YTM_MAX_PRICE_AGE_DAYS` (30 дней); иначе пусто, расчёт остаётся в `ytm_calc`.
  По снапшоту `b9eed489e99b`: YTM у 107 бумаг (KASE 77, AIX 30); у 69 сделка старше порога, 131 бумага
  AIX не торговалась ни разу. Осталось:
  - Наверху таблицы остаются реальные, но необычные сделки (FFMFO1.1226 65,7%, MFMOb10 30,2%) —
    решить, нужна ли пометка.
  - Оценка YTM по котировкам (bid/offer) для бумаг без сделок — не делалась.
  - **SKKZ.1126:** в проспекте погашение 05.11.2026, AIX показывает 05.09.2027. Новости о продлении не
    найдено (раскрытия эмитента на AIX, сайт фонда, СМИ; 11.11.2026). Расчёт по дате AIX, в данных
    примечание `data_note`. Вернуться, если появится раскрытие.
  - **Бумаги за дни до погашения.** При свежей цене YTM всё равно взлетает (MFMOb10: погашение через
    день, 49%). Решено показывать как есть — так делают KASE и Cbonds; таблица по умолчанию
    сортируется по дате погашения.
  - **Мелкие сделки.** YTM 22–27% у NCOMb9, NCOMb10 — единичные сделки на $100–3 700 по цене в
    стороне от номинала. Правило минимального объёма сделки не вводилось.
  - **Доходность при размещении для бумаг без сделок.** У 129 из 131 бумаги AIX без сделок цена в
    данных — это цена размещения (поле «Issue price» на странице AIX). Идея: считать доходность на
    дату размещения от этой цены и показывать отдельно от рыночного YTM (варианты: только в
    карточке; в колонке YTM приглушённо; отдельная колонка). Считать именно на дату размещения:
    «на сегодня» от цены размещения выходит ерунда (BIL5.1227 — 23,7% вместо ~5%). Оговорки: у 104
    бумаг цена 100, и доходность равна купону; у MFKZ.1128 и MFKZ.0934 в поле не цена размещения
    (113,81 и 101,78) — проверить; у 12 бумаг плавающий купон. Решение не принято.
- **Дата начала обращения.** По проспектам — дата первых состоявшихся торгов по размещению. Для
  12 бумаг без опубликованной даты погашения сейчас берётся дата открытия торгов — уточнить источник.

## Размещение сайта

Решения на 12.11.2026:

- **Хостинг — Amvera** (amvera.ru), тариф «Начальный Плюс» (1 ГБ памяти, 490 ₽ за 30 дней). Причины:
  нужна доступность из России, а доступ к GitHub оттуда в 2026 году дважды нарушался; расписание
  GitHub Actions неточное. На 500 МБ не хватает памяти: первый прогон с распознаванием проспектов
  занимает 691 МБ.
- **Один контейнер** (`Dockerfile`, `amvera.yaml`): `python -m kzbonds.serve` по расписанию обновляет
  данные (`kzbonds/scheduler.py`) и отдаёт страницу. База, кэши и собранная страница лежат в `/data` —
  постоянном хранилище Amvera.
- **Один шаблон страницы** — `kzbonds/site_template.html`. Из него `kzbonds/site.py` собирает и сайт
  (`--mode site`), и версию для артефакта (`--mode artifact`). Артефакт остаётся черновиком для правок
  дизайна; на сайт правка попадает отдельным шагом после отдельного согласия.
- **Сайт собирается из ветки `site`**, не из рабочей. Amvera привязана к ней вебхуком GitHub (ручная
  настройка, без токена). Проект в Amvera — `kazbonds`, пользователь `monitor`, регион Москва (`msk1`).
- **Расписание** (`KZBONDS_SCHEDULE_TIMES`, время Астаны, пн–пт), согласовано 12.11.2026:
  10:45, 11:40, 12:45, 13:45, 14:45, 15:45, 16:45, 17:30, 17:50. Замер 12.11 с 16:47 до 18:10: KASE
  обновляет данные пачками раз в 3–6 минут, последние изменения пришли в 17:39; AIX обновил справочные
  цены в 17:18–17:20 при закрытии в 17:05. Прогон 10:45 добавлен ради прямых сделок KASE (с 10:30);
  публикует ли их биржа до 11:30, не проверено — посмотреть по снимкам через несколько дней.

Не проверено, выяснится на пробном запуске:

- отвечают ли KASE и AIX серверам Amvera;
- собирается ли `Dockerfile` на Amvera — локально Docker недоступен, сервис проверен запуском без контейнера;
- открывается ли бесплатный домен `…amvera.tech` из России.

Отложено:

- **Яндекс Метрика** — счётчик 114228320, код счётчика взят из Метрики как есть. Номер задаётся переменной
  `KZBONDS_METRIKA_ID` в Amvera; без неё и в версии для артефакта Метрики на странице нет. Вебвизор включён.
  Цели типа «Целевое событие» (условие «совпадает»), подробности — деревом в «Параметрах визитов»:
  - вкладки: `tab_chart`, `tab_note`, `tab_table` (только при смене вкладки по клику посетителя);
  - карточки: `card_table`, `card_chart`, `card_search` (строка открыта при тексте в поиске);
  - выбор фильтра — по значению: `filter_exchange_{kase,aix}`, `filter_currency_{usd,cny,eur,rub,aed,other}`,
    `filter_type_{fixed,discount,floating,sukuk,capitalization,other}`,
    `filter_maturity_{lt1,1_3,3_5,5plus,perpetual,nodate}`; снятие (крестик или отжатие) — `filter_clear`;
  - `search`, `search_empty` (0 строк), `sort`, `reset_filters`.
  Поиск засчитывается, когда посетитель закончил с запросом: следующее действие (карточка, фильтр,
  сортировка, вкладка, Enter, уход из поля), 5 секунд без ввода, закрытие страницы или полное стирание
  поля (тогда уходит текст до стирания). «Уточнял» — стирал и печатал снова. Группы целей
  (`filter_currency_` и т. п., «содержит»; «любое действие» — регулярное выражение) заводятся только в Метрике.
  Уведомление посетителей и страницу политики решено не делать. Условия Метрики (п. 2.1, 5.8) требуют
  сообщать посетителям об обработке данных и о «Блокировщике Яндекс Метрики» — это решение владельца.
- Свой домен. Для `.ru` и `.рф` с 01.09.2026 нужно подтверждение через Госуслуги; `.kz` требует сервера
