# KZ Bond Monitor

Портфолио-продукт на основе двух скраперов валютных облигаций: единая
таблица KASE + AIX с YTM, дюрацией и флагом качества цены, автопайплайн
сбора данных и аналитическая записка с выводом, пересчитываемым на каждом
прогоне. Дашборд — Streamlit.

## Архитектура

```
kzbonds/
  sources/kase.py    # сбор + расчёты KASE (адаптировано из KASE_bonds_v4.py)
  sources/aix.py      # сбор + расчёты AIX (адаптировано из AIX API-скрапера)
  normalize.py        # единая схема полей + флаг price_quality
  db.py                # хранение снапшотов (SQLite по умолчанию, через SQLAlchemy)
  analysis.py          # генерация аналитической записки (markdown)
  pipeline.py          # оркестрация: fetch -> normalize -> save -> note
app.py                 # Streamlit-дашборд
scripts/run_pipeline.py  # CLI для cron/scheduler
docker/                # Dockerfile, docker-compose, фоновый scheduler
```

Каждый прогон пайплайна пишет **новый снапшот** (не перезаписывает старый),
с `run_id`/`fetched_at`. Это даёт историю по времени и позволяет спокойно
добавлять новые поля позже — старые снапшоты просто читаются с NULL в
новых колонках.

### Единая схема и флаг качества цены

`kzbonds/normalize.py` — единственное место, где меняется набор полей и
логика `price_quality`. Сейчас: `OK`, `STALE_OR_ESTIMATED` (фоллбэк:
HTML-парсинг, кэш профиля, купон из текста), `ILLIQUID` (нет цены/сделок
сегодня), `NO_PRICE`, `NO_YTM`, `CAPITALIZING` (капитализация купона,
YTM не считается), `FLOATING` (плавающая ставка, ставка неизвестна).
Набор полей и фильтров задумывался как незакреплённый — расширяйте
`UNIFIED_COLUMNS` и словарь `_FLAG_TO_QUALITY` там же.

### Аналитическая записка

`kzbonds/analysis.py::generate_note` считает по последнему снапшоту
(только бумаги с `price_quality == OK`) медианный YTM по валюте и корзине
дюрации на каждой бирже и делает конкретный вывод — где расхождение в
доходности между KASE и AIX больше всего при сопоставимом риске. Плюс
топ-5 доходностей по валютам. Это стартовый ракурс анализа, не
единственно возможный — логику легко заменить/дополнить.

## Быстрый старт (локально)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env

python scripts/run_pipeline.py     # первый сбор данных (1-3 минуты)
streamlit run app.py               # дашборд на http://localhost:8501
```

Кнопка «Обновить сейчас» в дашборде запускает пайплайн вручную из UI.

## Запуск через Docker (рекомендуется для сервера/VPS, в т.ч. Yandex Cloud)

```bash
cp .env.example .env
docker compose -f docker/docker-compose.yml up -d --build
```

Поднимает два сервиса на общем volume с SQLite-файлом:
- `dashboard` — Streamlit на порту 8501
- `scheduler` — фоновый цикл, обновляет данные каждые
  `KZBONDS_PIPELINE_INTERVAL_HOURS` часов (по умолчанию 6)

Подробности деплоя на Yandex Cloud (важно для доступности из России —
без завязки на западные PaaS с неопределённой геодоступностью) —
см. `docs/DEPLOY_YANDEX_CLOUD.md`.

## Тесты

```bash
pytest tests/ -q
```

Юнит-тесты покрывают приоритет флагов качества (`test_normalize.py`) и
корректность вывода аналитической записки (`test_analysis.py`). Сетевой
слой (`sources/kase.py`, `sources/aix.py`) не мокается тестами — это
живые скраперы сторонних API без официального SLA; проверяйте их
реальным прогоном `python scripts/run_pipeline.py` перед релизом.

## Известные ограничения / что дальше

- **SQLite под конкурентной записью**: `scheduler` и кнопка «Обновить
  сейчас» в дашборде могут одновременно писать в один файл — при частых
  ручных обновлениях возможна кратковременная блокировка (SQLite сам
  ретраит). При росте нагрузки — переключить `DB_URL` на Managed
  PostgreSQL (код не меняется).
- **AIX ISIN** пока не подтягивается (нет в текущем API-профиле) —
  колонка `isin` для AIX пустая.
- **Доступность kase.kz / market-backend.aixkz.com из России**: обе
  биржи казахстанские, блокировок на текущий момент не выявлено, но
  это внутренний недокументированный API AIX без SLA — при сбоях
  проверяйте `docker logs` scheduler-сервиса в первую очередь.
- Набор полей/фильтров в дашборде — стартовый (по договорённости), легко
  расширяется через `normalize.UNIFIED_COLUMNS` + `app.py`.
